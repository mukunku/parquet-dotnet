# #312: [BUG]: Loss of precision for DateTime milliseconds

- **State:** closed (closed 2023-07-21)

- **Created:** 2023-04-24

## Description

### Library Version

4.8.1

### OS

Windows

### OS Architecture

64 bit

### How to reproduce?

1. Create a table with a `DateTimeDataField` using `DateTimeFormat.DateAndTime`
2. Add a row containing `new DateTime(9999, 12, 31, 23, 59, 59, 999, DateTimeKind.Utc)` (that is, 9999-12-31T23:59:59.999Z, or 253402300799999 milliseconds)
3. Write the table to a parquet file
4. Read the parquet file back and see that the value is 9999-12-31T23:59:59.998Z (i.e. off by one millisecond)

The issue comes down to the [ToUnixMilliseconds method](https://github.com/aloneguid/parquet-dotnet/blob/26ea729ac32de27b43f25ae08f9bb2f5a6efdfb9/src/Parquet/Extensions/OtherExtensions.cs#L28) using `TotalMilliseconds`, which is a double subject to loss of precision.

But there's another kind of rounding error if you use values prior to the epoch. For example, "1969-12-31T23:59:59.0001Z" (notice the fractional millisecond that should get truncated) round trips to "1969-12-31T23:59:59.001Z" (i.e. an extra millisecond).

For reference, check out the comments in [DateTimeOffset.ToUnixTimeSeconds](https://github.com/dotnet/runtime/blob/ab2b80d06dd4d997df5ffa72a3c4a99cb36ccbff/src/libraries/System.Private.CoreLib/src/System/DateTimeOffset.cs#L799) and their implementation of `ToUnixTimeMilliseconds` below it. Based on that, the most straightforward fix is to keep it as a long but also subtract _after_ the truncation to milliseconds:

```csharp
public static long ToUnixMilliseconds(this DateTime dto) {
    var milliseconds = dto.Ticks / TimeSpan.TicksPerMillisecond;
    return milliseconds - UnixEpoch.Ticks / TimeSpan.TicksPerMillisecond;
}
```

Though I've been wondering why use `DateTime` at all when `DateTimeOffset` both eliminates time zone ambiguity and provides `ToUnixTimeMilliseconds` and `FromUnixTimeMilliseconds` methods for you. As a middle ground, since the callers always ensure the `DateTime` is UTC before calling `ToUnixMilliseconds`, you could just convert to a `DateTimeOffset`: `return new DateTimeOffset(dto).ToUnixTimeMilliseconds();`.
