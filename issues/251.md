## Description

I am Parquet.Net (v4.4.5) to serialize data into Parquet using `ParquetRowGroupWriter`'s `WriteAsync` extension and passing in a `Table` object. From my understanding, the library converts the rows in the `Table` into columns (`DataColumn`) and then passes them to `WriteColumnAsync`.

After writing the Parquet I then want to write a Delta Lake log, and so I need access to the written columns to fetch columns statistics. Unfortunately it seems I can't access the converted columns as both `ExtractDataColumns` and `RowsToDataColumnsConverter` are marked as internal.
I was originally creating `DataColumn`s myself and calling `WriteColumnAsync` directly, but moved to use the `Table`-based `WriteAsync` to get support for struct types.

Is there any way I can still access the underlying converted columns? Is there an alternative?

## Comments

### aloneguid on 2023-02-01

Ok they're not exposed because there may be multiple data columns per column, each with its own statistics that may be different as well, so it's hard to figure out what to return. Remember row-oriented API is mostly for convenience and are extremely slow and inefficient.

You can continue using `DataColumn` with structs though, it's not that complicated. Have a look at unit tests that write all kinds of complex structures. Or as a faster path - write your data with table api, then read with datacolumn api and have a look what they return in data columns as an example ;)
