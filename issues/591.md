### How to reproduce?

While reading a Parquet file using Parquet-dotnet v3.10.0, I encountered an issue where values for a specific column, pathOrInlineDv, become corrupted or incorrect after reading approximately 2000 rows.

This issue occurs when processing checkpoint Parquet files in Delta Lake. I have verified this behavior by comparing the results from v3.10.0 and v4.10.0, where the latter correctly reads all values.

Upgrading to v4.10.0 resolves the issue, but it introduces breaking changes in our application. I am looking for insights on:

Identifying the root cause in v3.10.0.
- A possible workaround or backport fix without upgrading to v4.10.0.
- Attached is an Excel file comparing the outputs from both versions, highlighting the incorrect values in v3.10.0.

Below code fails to read the data correctly.
`Array primaryDataFieldColumnData = groupReader.ReadColumn(primaryDataField).Data;`
