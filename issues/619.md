## Description

### Issue description

First of all, thank you for this library. I have encountered an issue - one of my model fields has to be [JsonIgnore]d as it's not a part of my public API contract, but rather an auxiliary metadata. However, when dumping those models to Parquet I want to preserve this metadata as it's useful for diagnostics.

Right now a presence of a `[JsonIgnore]` or a `[ParquetIgnore]` attribute always excludes field from Parquet serialization. While retaining this behavior is important for backwards compatibility, would it make sense to have an ability to un-exclude the field (possibly, with `[ParquetIgnore(false)]` or `[ParquetInclude]` or something like that)?

I could be doing something weird, but I believe I have a case where JSON and Parquet data can be considered to serve different use cases, and  that there should be an ability to have some fields present in Parquet and not in JSON (vice versa is already possible with `[ParquetIgnore]`). Thank you!
