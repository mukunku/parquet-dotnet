## Description

**Version:** Parquet.Net v 3.9.1

**Runtime Version:** .Net Framework v net472

**OS:** Windows10

#### Expected behavior

I would expect parquet-dotnet to allow scale = 0 for DecimalDataFields

#### Actual behavior

parquet-dotnet raises an error:

`System.ArgumentException: 'scale cannot be less than 1
Parameter name: scale'`

### Steps to reproduce the behavior

Attempt to create a parquet schema with a DecimalDataField with scale = 0

#### Code snippet reproducing the behavior

<!-- Please include a code snippet so we can reproduce the problem. An ideal code snippet is a failing unit test ;) -->

```csharp
var schema_fields = new Parquet.Data.DataField[]
{
    new Parquet.Data.DecimalDataField(name: "Test", precision: 38, scale: 0)
};
var parquetSchema = new Parquet.Data.Schema(schema_fields);
```

I know it is a bit of an odd request, but I often work with legacy SQL Server Databases that use data types such as Decimal(20,0) as a way to allow large integers numbers.
