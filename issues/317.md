## Description

### Issue description

We are using the latest version of the library (4.10.1) and writing record values coming from a database table to parquet files. In case of decimals, we noticed that the value being serialized is actually sent as byte array. Here is the json reprentation of one sample value when reading the file content with the parquet-viewer extension for VS Code:

"PRODUCTID":{"type":"Buffer","data":[0,0,0,0,0,0,0,0,13,224,182,179,167,100,0,0]}

Using the parquet viewer application we get this error: 
![image](https://user-images.githubusercontent.com/38789498/236209734-137c6f7d-1f9b-4123-91be-db3029ca0500.png)

We load data to parquet using the ParquetSchema and the type definition is decimal, but couldn't find any way to modify or customize the serialization. Notice this used to work fine with a previous version (3.9) of the library. Any hint?

These are the steps we are following:
- we build a Parquet.Schema.ParquetSchema from a list of DataFields. The fields that are marked as Decimal are defined with the ParquetType = System.Decimal. Here is an example of such schema (notice the ProductID column): 
![image](https://user-images.githubusercontent.com/38789498/236237284-da2cb5fa-2159-46f9-9180-b6517ac1ba7c.png)

- we load the data into a DataTable
- we create a ParquetWriter and set the schema to the schema object previously loaded: 
   `ParquetWriter parquetWriter = ParquetWriter.CreateAsync(m_cParquetRecordSchema, outStream)` 
- we go through each record in the DataTable and append a new row in a ParquetTable object. This is an example of one row of the parquet table: 
![image](https://user-images.githubusercontent.com/38789498/236239038-da22323e-3a01-4f4d-bc44-9b4360f94878.png)

- we use the ParquetWriter to write the parquet table to file: 
   `parquetWriter.WriteAsync(parquetTable)`

If we open the parquet file generated, we get the error uploaded earlier. From the parquet-viewer extension for VS Code we can check the schema which shows incorrectly a byte array for the column ProductID.
