## Description

### Issue description

In [this line](https://github.com/aloneguid/parquet-dotnet/blob/068b98750a179c6ae9afeaa420c60713bfb2620c/src/Parquet/Meta/Proto/ThriftCompactProtocolReader.cs#L192) in the `ThriftCompactProtocolReader`, when skipping over a thrift struct, we read the field id and type within the struct. I think that additionally, we have to skip over the field itself in the loop, similar to how it is done for skipping a list.

I think this might be the root cause for #576 and #579: When parquet files had a new struct field in the column metadata, this field was not cleanly skipped over, leading to incorrect reads of later fields. Until the skipping is fixed, we might run into the same issue when other unknown fields are encountered.
