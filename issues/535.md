## Description

### Library Version

4.25.0-pre.2

### OS

Windows

### OS Architecture

64 bit

### How to reproduce?

1. Deserialize simple parquet file with schema (obtained from Tad - the parquet file also crashes floor)
![image](https://github.com/user-attachments/assets/1a4e5883-bf50-43f4-a2fd-f4fd3b332114)

2. "System.IO.InvalidDataException: 'property 'Value' is declared as 'value (System.String?)' but source data has it as 'value (System.String)''"

with 
```csharp
public class MyClass 
{
    [JsonPropertyName("id")]
    public long Id { get; set; }

    [JsonPropertyName("value")]
    public string Value { get; set; } = null!;

    [JsonPropertyName("frequency")]
    public double Frequency { get; set; }
}
```

The important part to note is that the exception is the same whetever Value is defined as nullable or not.
```csharp
    [JsonPropertyName("value")]
    public string? Value { get; set; } = null!;
``` 

ends up with exactly same error message. 

### Failing test

```csharp
var records = await ParquetSerializer.DeserializeAllAsync<MyClass>(stream).ToListAsync();
```

I added unit tests in my PR to show the issue.

```csharp
        class PocoClassNotNullable {
            [JsonPropertyName("id")]
            public long Id { get; set; }

            [JsonPropertyName("value")]
            public string Value { get; set; } = null!;

            [JsonPropertyName("frequency")]
            public double Frequency { get; set; }
        }

        [Fact]
        public void Strings_NotNullable() {
            ParquetSchema s = typeof(PocoClassNotNullable).GetParquetSchema(true);
            Assert.False(s.DataFields[0].IsNullable);
            Assert.False(s.DataFields[1].IsNullable);
            Assert.False(s.DataFields[2].IsNullable);
        }
```

This fails with current version. The current code will consider any string as nullable, so I don't think you can deserialize a non nullable string in parquet to a class unless you add `[ParquetRequired]` to that field. This is because the Roslyn annotations are not used so any string is technically nullable.
