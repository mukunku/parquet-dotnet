## Description

### Issue description

Just a placeholder. Row API are too inflexible and just increase complexity unnecessarily. 

I'm thinking of replacing it with "cell API" (name might change and up for discussion).

Essentially what they will do is allow to read a column as a collection of typed objects. Something like low-level API, but taking into account complex data structures.

How it will work:
1. In addition to reading column as `DataColumn` you will have a method to read it as `ICollection`.
2. The collection type depends on underlying column - it can be `DataField`, `StructField`, `MapField` or `ListField`.

Pros:
1. Unlike low-level API, you can create complex structures easier, without decomposing into internal parquet columns (structs, maps etc.)
2. Much higher performance.
