# #343: [BUG]: `DataFrameMapper` returns incompatible DataFrameColumn

- **State:** closed (closed 2023-12-22)
- **Author:** DavidLHW
- **Created:** 2023-05-31
- **Original URL:** https://github.com/aloneguid/parquet-dotnet/issues/343
- **Recovery status:** Recovered

## Description

### Library Version

4.12.0

### OS

all

### OS Architecture

ARM 64

### How to reproduce?

1. Write & save parquet file with `ParquetSerializer.SerializeAsync`:

    ```F#
    open Parquet.Serialization

    let records = [
        {| Name = "Test1"; I64Value = 1L; |}  // `I64Value` here is never null
        {| Name = "Test2"; I64Value = 2L; |}
        {| Name = "Test3"; I64Value = 3L; |}
        //             :
        //             :
    ]

    ParquetSerializer.SerializeAsync(records, "/tmp/test.parquet").GetAwaiter().GetResult()
    ```

2. Read with `ReadParquetDataFrameAsync`

    ```F#
    open System.IO
    open Parquet

    let fs = File.OpenRead("/tmp/test.parquet")
    let df = fs.ReadParquetAsDataFrameAsync().GetAwaiter().GetResult()
    ```

3. call `GetInt64Column`

    ```F#
    let v = df.Columns.GetInt64Column("I64Value")
    ```

Error Stack
```
Error: System.ArgumentException: Cannot cast column holding System.Int64 values to type System.Int64
at Microsoft.Data.Analysis.DataFrameColumnCollection.GetInt64Column(String name)
```

---

After some investigation, this seems to be caused by [this line](https://github.com/dotnet/machinelearning/blob/aca80057756bceb4308a51475d8d15be34ae6f1f/src/Microsoft.Data.Analysis/DataFrameColumnCollection.cs#L364) under the `Microsoft.Data.Analysis` package.

```C#
public Int64DataFrameColumn GetInt64Column(string name)
{
    DataFrameColumn column = this[name];
    if (column is Int64DataFrameColumn ret)  // line causing the problem
    {
        return ret;
    }

    throw new ArgumentException(string.Format(Strings.BadColumnCast, column.DataType, typeof(Int64)));
}
```

`Int64DataFrameColumn` is implemented as

```C#
namespace Microsoft.Data.Analysis
{
    public partial class Int64DataFrameColumn : PrimitiveDataFrameColumn<long>
    {
        public Int64DataFrameColumn(string name, IEnumerable<long?> values) : base(name, values) { }

        public Int64DataFrameColumn(string name, IEnumerable<long> values) : base(name, values) { }

        public Int64DataFrameColumn(string name, long length = 0) : base(name, length) { }

        public Int64DataFrameColumn(string name, ReadOnlyMemory<byte> buffer, ReadOnlyMemory<byte> nullBitMap, int length = 0, int nullCount = 0) : base(name, buffer, nullBitMap, length, nullCount) { }

        internal Int64DataFrameColumn(string name, PrimitiveColumnContainer<long> values) : base(name, values) { }
    }
}
```

while `DataFrameMapper` returns `PrimitiveDataFrameColumn` so the check `(column is Int64DataFrameColumn ret)` would throw exception even if types are compatible.

---

Not too sure if this behaviour is intentional or just an oversight, but for anyone else facing a similar issue, a sensible workaround would be for the caller to do something like:

```F#
let v = df.Columns.GetPrimitiveColumn<int64>("I64Value")
```
