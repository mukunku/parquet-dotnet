# #630: [BUG]: Serialize doesn't handle empty + null list of nullable type

- **State:** open
- **Author:** mrinal-thomas
- **Created:** 2025-07-20
- **Original URL:** https://github.com/aloneguid/parquet-dotnet/issues/630
- **Recovery status:** Recovered

## Description

### Library Version

5.1.1

### OS

All

### OS Architecture

ARM 64

### How to reproduce?

When serializing a list of strings (or other nullable item type), the parquet serializer will serialize:
* a null list to an empty list
* an empty list to a list with one null item.

This is because FieldStriperCompiler uses [itemMaxDL - 2](https://github.com/aloneguid/parquet-dotnet/blob/master/src/Parquet/Serialization/Dremel/FieldStriperCompiler.cs#L323) and [itemMaxDL - 1](https://github.com/aloneguid/parquet-dotnet/blob/master/src/Parquet/Serialization/Dremel/FieldStriperCompiler.cs#L329) for null and empty list. However, this only works when the item type is non-nullable.

Suggested fix: use `listMaxDL - 2` and `listMaxDL - 1`. This should work regardless of item nullability.


### Failing test

```csharp
public class TestRow
{
    public int ID { get; set; }
    public List<int> Numbers { get; set; } = []; // This serializes properly
    public List<string> Words { get; set; } = []; // This doesn't
}

public class Program
{
    public static async Task Main(string[] args)
    {
        TestRow[] rows = [
            new TestRow { ID = 1, Numbers = [456], Words = ["abc"]},
            new TestRow { ID = 2, Numbers = [], Words = []},
            new TestRow { ID = 3, Numbers = [null], Words = [null]},
            new TestRow { ID = 4, Numbers = null, Words = null}
        ];
        string testFile = "test.parquet";

        await ParquetSerializer.SerializeAsync(rows, testFile);
    }

}
```
