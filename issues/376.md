## Comments

### VolodymyrSenchak on 2023-08-02

Oh, thanks for replying. Actually, even existing functionality with row API should help me (parsing files will happen in the background process, so I can neglect some performance degradation) 
I'm currently gathering all cases which can be in our project, and I suspect that files could have different structures depending on the case. 
And since currently Class Serialisation approach will throw an exception when some property will not be found in file - I see two options:
1  - parse file with some base class which will try to identify which type structure file has, and then a second time with the appropriate type. But from a performance perspective, it would also be not ideal, because it will be needed to parse the file twice.
2 - by using row API parse file to JSON, and then parse it to some aggregate class. 

Maybe you could suggest how I can solve that issue when a parquet file can have a dynamic structure?

### aloneguid on 2023-08-02
