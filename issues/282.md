### How to reproduce?

I'm encountering problems with serialization of nested null values. Results of serialization->deserialiation can interpret the null at the wrong level.

I encountered issues working with the Table API  with nested arrays, but when I tried to put together a minimal breaking example, I found this relatively simple case that leads to failure with the Class API, without arrays.

### Failing test

Try this test in `ParquetSerializerTest.cs`:

```csharp
        [Fact]
        public async Task Struct_Serde_With_NestedNulls() {

            var data = new List<AddressBookEntry> {
                new AddressBookEntry {
                    FirstName = "Joe",
                    LastName = "Bloggs",
                    Address = new Address() {
                        City = null,
                        Country = null
                    }
                }
            };

            using var ms = new MemoryStream();
            await ParquetSerializer.SerializeAsync(data, ms);

            ms.Position = 0;
            IList<AddressBookEntry> data2 = await ParquetSerializer.DeserializeAsync<AddressBookEntry>(ms);

            Assert.Equivalent(data2, data);
        }
```

### Mrinal-Thomas-Epic on 2023-04-10

@aloneguid I think the issue is that for optional fields. In [`UntypeArrayExtensions.cs`](https://github.com/aloneguid/parquet-dotnet/blob/master/src/Parquet/Extensions/UntypedArrayExtensions.cs#L484) when packing null values, you are setting definition level to either max DL (when the value is defined) or 0 (when the value is null). To support nested optional structures in parquet, you have to set the DL based on the level at which the value is not defined.

My recommendation would be:
1) [`ParquetSerializer.SerializeAsync`](https://github.com/aloneguid/parquet-dotnet/blob/master/src/Parquet/Extensions/UntypedArrayExtensions.cs#L484) should pass in false for the `unpackDefinitions` parameter when creating a `DataColumn`.
1.1) The DataColumn constructor that takes in definition levels should be made public, so that consumers of the column-based API can provide definition levels.
2) If [`PackedColumn.Pack`](https://github.com/aloneguid/parquet-dotnet/blob/master/src/Parquet/File/PackedColumn.cs#L145) is called with a `DataColumn` that already has definition levels, use the existing definitions levels.
