# #588: Feature Request: Full Nanosecond precision support

- **Recovery status:** Recovered

## Description

### Issue description

Currently TIME and TIMESTAMP Parquet.NET elements support millisecond precision values. Microsecond precision was added for later versions of .NET, but actual nanosecond precision is not truly supported.

All "date and time" values are supported only by using the DateTime CLR type, which is inadequate for storing nanosecond precision.

My organization is involved in collecting and processing testing data that is more precise than System.DateTime. As such we cannot use Parquet.NET for reading/storing actual timestamps as intended unless we use tools that are not based on Parquet.NET...which adds inefficiencies for our analysts.

I propose that a "Primitive" type be added to Parquet.NET that handles all Parquet time and timestamp precisions correctly. NanoTime.cs appears to only facilitate INT96 usage, which has been deprecated.

NOTE: and INT64 can represent nanosecond-precision until the year 2262, so INT96 shenanigans are not requested, needed, or wanted.

I realize that we can store true nanosecond-precision timestamps as an INT64 field, but there is no mechanism within Parquet.NET to support the values as actual date-and-time timestamps. So any values written into Parquet by other apps or tools will necessarily be truncating the actual values when processed using Parquet.NET.
