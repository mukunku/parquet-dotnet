## Description

### Library Version

5.2.0

### OS

Windows

### OS Architecture

64 bit

### How to reproduce?

When producing a parquet file containing a Boolean column the files will produce slightly different checksums each time if the row count per row group is quite high. I traced this down to the following method in "ParquetPlainEncoder.cs"

`public static void Encode(ReadOnlySpan<bool> data, Stream destination)`

When it is getting the target length it adds an extra 1 on but if the row number is divisible by 8 then it causes an extra random byte from the rented array to be written to the file. It doesn't seem to effect the output but it causes the file to hash differently.

I believe the fix is just changing the line
`int targetLength = (data.Length / 8) + 1;`
To this
`int targetLength = (data.Length / 8) + (data.Length % 8 == 0 ? 0 : 1);`


### Failing test


Make a parquet file with Boolean columns where the row group size is divisible by 8.
