## Description

**Version:** Parquet.Net v...

**Runtime Version:** .Net Framework 472

**OS:** Windows

#### Expected behavior

Parquet schema with 2 nested structs throws a null reference exception when writing using Row based api in RowValidator.cs.
This happens when use set one of the nested structs to null.

#### Actual behavior

Throws null reference exception with below stacktrace.
`
    System.NullReferenceException: Object reference not set to an instance of an object.
  Stack Trace: 
    RowValidator.Validate(Row row, IReadOnlyList`1 fields)
    RowValidator.Validate(Row row, IReadOnlyList`1 fields)
    Table.Add(Row item)
`
Based on [Validate](https://github.com/aloneguid/parquet-dotnet/blob/3f3f070419ab1a9f9a86f2cc0f39ce07aaf92673/src/Parquet/Data/Rows/RowValidator.cs) method, we would get null reference exception. 
Is there a way to write null?
#### Code snippet reproducing the behavior

<!-- Please include a code snippet so we can reproduce the problem. An ideal code snippet is a failing unit test ;) -->

```csharp
            var schema = new Schema(
                new StructField("c1", new DataField("ic2", DataType.String), new DataField("ic2", DataType.String)),
                new StructField("c2", new DataField("ic2", DataType.String), new DataField("ic2", DataType.String)));
            var row = new Row(
                new Row("t2", "t22"),
                null);
            var stream = new MemoryStream();

            using (var parquetWriter = new ParquetWriter(schema, stream))
            {
                using (var rowGroup = parquetWriter.CreateRowGroup())
                {
                    var parquetTable = new Table(schema);

                    parquetTable.Add(row);
                    rowGroup.Write(parquetTable);
                }
            }
```
Updating RowModelTests with null also reproduces it.

