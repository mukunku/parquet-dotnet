## Description

### Issue description

I'm converting some data with lots of UTF8-encoded strings into Parquet.
Reading the data as strings in C# means more allocation and more memory usage (as it uses UTF16).
Reading the data as `byte[]` or `Span<byte>` works well, but this library doesn't seem to support writing them as string in Parquet, even with the low level API.
When I create a schema with `new DataField<string>(columnName)`, but write with `new DataColumn(dataField, arrayOfBytes)`, this exception is raised:
```
System.ArgumentException: expected System.String[] but passed System.Byte[][] (Parameter 'data')
```

## Comments

### aloneguid on 2023-06-28

You can write data as `byte[]` by declaring `DataField<byte[]>` and then put whatever content, bypassing all the "ineffectiveness".

### cfbao on 2023-06-28

I've tried that, but IIUC, `DataField<string>` and `DataField<byte[]>` write different metadata, and that has an impact on the consumer of the parquet file. We don't own the consumer in this case.

What I'd like is to be able to write `byte[]` while still having the right metadata for strings, so the consumer will naturally parse the data as strings.

### aloneguid on 2023-06-28

We would have to check that byte arrays are actually strings by constructing them, also internal compression needs strings, so I'm not sure what we are winning by allowing to create potentially malformed file.

### cfbao on 2023-06-29

If the library really allows creating malformed file, then it doesn't need UTF-8 validation. 😉

However, we can actually validate UTF-8 byte arrays without constructing strings:
```csharp
using System.Text;

var b = new byte[] { 200, 211, 222 };
var utf8 = new UTF8Encoding(encoderShouldEmitUTF8Identifier: false, throwOnInvalidBytes: true);

try
{
    utf8.GetCharCount(b);
}
catch (DecoderFallbackException)
{
    Console.WriteLine("Invalid UTF-8 byte array!");
}
```
So we can have the best of both worlds.

I don't know how the internal compression works, but why wouldn't normal `byte[]` compression work? Does the current compression implementation also constructs strings for byte array columns? Maybe a pointer to the relevant code area can help me understand.

### aloneguid on 2023-06-29

Current dictionary compression implementation works only on string objects. I guess implementing it for byte arrays would be beneficial too. Without dictionary compression file sizes will be quite large. 

I think your best approach will be:
1. implement dictionary compression for `byte[]` - optional but highly recommended.
2. write data as byte arrays.
3. Just before disposing `ParquetWriter` modify schema element to string metadata (schema is written on stream on dispose).
