## Description

### Library Version

4.8.0 and higher

### OS

Windows

### OS Architecture

64 bit

### How to reproduce?

1. Serialize object with array collection using ParquetConvert class and parquet.net@4.7.1 . Store result file  and try to deserialize (all work nice)
```csharp

public class Dto
{
    public IReadOnlyCollection<string> HarmlessCollection { get; set; }
}

var dataToWrite = new List<Dto>
{
    new()
    {
        HarmlessCollection = new List<string>() { "Hello" }
    }
};


using (var stream = File.Create("tmp.parquet"))
{
    ParquetConvert.SerializeAsync(dataToWrite, stream).GetAwaiter().GetResult();
}

using (var stream = File.OpenRead("tmp.parquet"))
{
    var result = ParquetConvert.DeserializeAsync<Dto>(stream).GetAwaiter().GetResult();
}
```
2. Replace ParquetConvert with ParquetSerializer, update Colelction type to List<T> and perform and try to deserialize file from previous run (all works)
```csharp

public class Dto
{
    public List<string> HarmlessCollection { get; set; }
}

using (var stream = File.OpenRead("tmp.parquet"))
{
    var result = ParquetSerializer.DeserializeAsync<Dto>(stream).GetAwaiter().GetResult();
}
```
3. Update to  parquet.net@4.7.1 and try to run deserialization from step 2. ParquetException with error message "'HarmlessCollection/list/element' does not exist in this file" will be thrown. The same issue is relevant for latest versions parquet.net@4.12.0.

So it seems like ParquetSerializer used to deserialize array collections produced by ParquetConvert nicely before 4.8.0 version.
This backward compatibility is important for our project as we already have gigs of data produced by deprecated ParquetConvert and would like to update to the lates version of this library and use ParquetSerializer without a need to re-process all the files we are storing now.
