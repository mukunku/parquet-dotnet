## Description

### Library Version

4.90 - 4.10.1

### OS

Windows 11

### OS Architecture

64 bit

### How to reproduce?

1. Run a unit test with the code below. reader.Schema.DataFields[0].ClrType is byte[] instead of decimal, which I suspect causes rowGroupReader.ReadColumnAsync(...) to fail with ArgumentOutOfRangeException. This test passes in Parquet.Net 4.8.1 but fails with 4.9.0 and newer versions.

### Failing test

```csharp
using System.Collections.Generic;
using System.IO;
using System.IO.Compression;
using System.Threading.Tasks;
using Parquet;
using Parquet.Data;
using Parquet.Schema;
using Parquet.Serialization;
using Xunit;

namespace TestLibrary {
    public class TestClass {
        [ParquetColumn(Name = nameof(Value), DecimalPrecision = 38, DecimalScale = 18)]
        public decimal Value { get; set; }
    }

    public class ReadDecimalTests {
        [Fact]
        public async Task RoundTrip() {
            // create test items to be serialised
            List<TestClass> inputItems = new List<TestClass>() {
                new TestClass()
                {
                    Value = 1.2m,
                },
            };

            // create Parquet stream
            MemoryStream ms = new MemoryStream();
            ParquetSerializerOptions options = new ParquetSerializerOptions() {
                Append = false,
                CompressionLevel = CompressionLevel.SmallestSize,
                CompressionMethod = CompressionMethod.Gzip,
            };
            ParquetSchema schema = await ParquetSerializer.SerializeAsync(inputItems, ms, options);

            // verify that the data field type is Decimal
            Assert.Single(schema.DataFields);
            Assert.Equal(typeof(decimal), schema.DataFields[0].ClrType);

            // create Parquet reader
            ms.Position = 0;
            ParquetReader reader = await ParquetReader.CreateAsync(ms);
            Assert.Single(reader.Schema.DataFields);

            // this test fails - ClrType is byte[]
            //Assert.Equal(typeof(decimal), reader.Schema.DataFields[0].ClrType);

            // read all values
            for(int rowGroupIndex = 0; rowGroupIndex < reader.RowGroupCount; ++rowGroupIndex) {
                using(ParquetRowGroupReader rowGroupReader = reader.OpenRowGroupReader(rowGroupIndex)) {
                    // throws ArgumentOutOfRangeException
                    DataColumn dc = await rowGroupReader.ReadColumnAsync(reader.Schema.DataFields[0]);
                }
            }
        }
    }
}
```

At https://github.com/aloneguid/parquet-dotnet/blob/162e425e92756a3d22c6c874379859d61561099d/src/Parquet/Encodings/SchemaEncoder.cs#L177

se.Type is `Type.FIXED_LEN_BYTE_ARRAY` and se.ConvertedType is null so the switch expression falls to 
https://github.com/aloneguid/parquet-dotnet/blob/162e425e92756a3d22c6c874379859d61561099d/src/Parquet/Encodings/SchemaEncoder.cs#L227
and the data field is treated as `byte[]`. Inspecting in the debugger, `se.LogicalType.DECIMAL` is not null so I guess `se.LogicalType` should be used as as the type hint, similar to https://github.com/aloneguid/parquet-dotnet/blob/162e425e92756a3d22c6c874379859d61561099d/src/Parquet/Encodings/SchemaEncoder.cs#L222
