## Description

**Version:** v3.91

**Runtime Version:** NET 4.6.2 and NET6

**OS:** Windows

#### Expected behavior

One million byte array written to Parquet should be around 1 MB filesize + Parquet memory overhead for file structure and schema values.

#### Actual behavior

One million byte array (as per example) written to Parquet is around 9 MB. This is linear across all sizes. 1 GB becomes ~9 GB etc. Same issues with very large strings.

### Steps to reproduce the behavior

1. Create an appropriate DataColumn, Schema, Field, and array of byte[] (byte[][]);
2. Create a ParquetWriter, TreateByteArrayAsString = false, CompresionMethod Snappy or None (doesn't change).
3. Create a RowGroup.
4. Write the one DataColumn.
5. Observe the output file size is vastly larger than expected.

Additional Details:
This example is using random bytes and thus will not compress very well.
I have included just a raw base64 conversion which shows around 33% increase due to base64 string encoding.

As before with my last issue, and this is a real issue and not just my Parquet ignorance, happy to help out but would love a point in the right direction.

#### Code snippet reproducing the behavior

<!-- Please include a code snippet so we can reproduce the problem. An ideal code snippet is a failing unit test ;) -->

```csharp
public static async Task Parquet_FileSizeIssue_Reproducible_Async()
{
    var testStringFile = @".\test\test.txt";
    var testParquetFile = @".\test\test-000.parquet";
    var oneMillionBytes = 1 * 1024 * 1024;
    var rand = new Random();
    var data = new byte[1][];
    var bytes = new byte[oneMillionBytes];
    rand.NextBytes(bytes);
    data[0] = bytes;

    var field = new DataField("Data", typeof(byte[]));
    var schema = new Schema(field);
    var dataColumn = new DataColumn(field, data);

    if (!Directory.Exists("test"))
    { Directory.CreateDirectory("test"); }

    if (!File.Exists(testParquetFile))
    { File.Delete(testParquetFile); }

    using var fileStream1 = File.Open(testParquetFile, FileMode.OpenOrCreate);
    using var parquetWriter = new ParquetWriter(schema, fileStream1, formatOptions: new ParquetOptions { TreatByteArrayAsString = false, TreatBigIntegersAsDates = false })
    {
        CompressionMethod = CompressionMethod.Snappy,
    };

    using var rowGroupWriter = parquetWriter.CreateRowGroup();
    rowGroupWriter.WriteColumn(dataColumn);

    // Plain Base64 string representation of bytes.
    if (!File.Exists(testStringFile))
    { File.Delete(testStringFile); }

    using var fileStream2 = File.Open(testStringFile, FileMode.OpenOrCreate);
    using var streamWriter = new StreamWriter(fileStream2);

    await streamWriter.WriteLineAsync(Convert.ToBase64String(bytes));
}
```

    data[0] = new byte[oneMillionBytes];

    var columns = new ParquetSharp.Column[]
    {
        new Column<byte[]>("Data"),
    };

    using var file = new ParquetFileWriter(testParquetFile, columns, Compression.Snappy);
    using var rowGroup = file.AppendRowGroup();

    using (var dataWriter = rowGroup.NextColumn().LogicalWriter<byte[]>(1024*1024))
    {
        dataWriter.WriteBatch(data);
    }

    // Plain Base64 string representation of bytes.
    using var fileStream2 = File.Open(testStringFile, FileMode.OpenOrCreate);

    await streamWriter.WriteLineAsync(Convert.ToBase64String(data[0]));
