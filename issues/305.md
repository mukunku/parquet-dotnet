## Description

### Issue description

I am looking into this library as an option to generate parquet files. I noticed the files generated by this library do not use Logical Types, we are only using Converted Types. If I use ParquetSharp I get Converted Types, but I would like to avoid using unmanaged code. Can you please clarify on why you do not support Logical Types and if there is any work being done in this area?

## Comments

### aloneguid on 2023-04-20

Thank you for asking the question. Currently, I find that ConvertedType is suitable for representing encoded types, and for backward compatibility, all readers are required to support it. While LogicalType can be useful for encoding decimals and Guids with richer information, I am unable to discern its broader usefulness. If it's not too much trouble, would you mind sharing your specific use case with me?

### lourencoteodoro on 2023-04-20

I have found the same as you described. The main concern is if we implement a system that does not support logical types, but in the future logical types are added, that the file would be different (not a big deal, as it would still be compatible). I guess the main problem is just the impression we are not complying with the latest standard, even though I have not fully understood the motiviation behind this change in the standard.
